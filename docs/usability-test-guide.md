# Bonded Agent 可用性测试指南

> 给不懂技术的队友：这份指南不需要任何编程知识，跟着步骤走就行。

---

## 准备工作（5 分钟）

让 Dev 队友帮你完成以下准备，你只需要打开浏览器：

1. **安装 MetaMask 钱包插件**（如果还没有）
   - Chrome：https://metamask.io/download/
   - 装好后创建或导入一个钱包

2. **添加 Monad 测试网**
   - 让 Dev 帮你加，或者点 MetaMask 顶部网络下拉 → "Add custom network"：
     - Network Name: `Monad Testnet`
     - RPC URL: `https://testnet-rpc.monad.xyz`
     - Chain ID: `10143`
     - Currency Symbol: `MON`

3. **领测试币**
   - 让 Dev 给你转一点 MON 和 tUSDC

4. **打开测试页面**
   - Dev 会给你一个本地地址，比如 `http://localhost:3000`

---

## 测试任务（15 分钟）

### 任务 1：连接钱包 + 获取报价

1. 打开测试页面
2. 点右上角 **「连接钱包」**，MetaMask 弹出来后确认
3. 输入框中填入你想换的 MON 数量（默认 1）
4. 点 **「获取担保报价」**
5. 看看页面上显示的内容——

> **此时请回答**：你知道你付多少钱、预计拿到多少钱吗？页面有没有你看不懂的词？

---

### 任务 2：阅读理解承诺卡片

报价出现后，你会看到一张**承诺卡片**，上面写着：

- **预期输出**：AI 模拟的结果（比如 100 tUSDC）
- **担保底线**：运营方保证你最少能拿到的（比如 90 tUSDC）
- **锁定保证金**：运营方压在合约里的钱（比如 20 tUSDC）
- **失败补偿**：交易完全失败时额外赔你的
- **有效期**：这份保证的截止时间

> **此时请回答**：
> 1. 你知道谁在提供保证金吗？
> 2. 如果到账比保证的少，谁会赔你钱？
> 3. 你觉得这个承诺卡有什么不清楚的地方？

---

### 任务 3：生成担保计划 + 执行

1. 点 **「生成担保计划」**
2. MetaMask 弹出确认，点确认（这是链上交易，需要几秒）
3. 页面自动跳转到计划详情
4. 点 **「同意并执行 Swap」**
5. MetaMask 再次确认

> **此时请观察**：等待过程中页面显示了什么？结算完成后你看懂结果了吗？

---

### 任务 4：查看 tUSDC 余额变化（关键！）

执行前后各看一次余额，数字的变化比文字解释更直观。

**如何查看 tUSDC 余额：**
1. 打开 MetaMask 插件
2. 往下滚动到 **"Tokens"** 区域
3. 点底部的 **"Import tokens"**
4. 填入合约地址：`0xD5B1b42929188280631ef2502c78AA61e1A56e0a`
5. 代币符号会自动显示为 `tUSDC`，点确认

**测试步骤：**
1. **执行计划前**：记下你当前的 tUSDC 余额（比如 1000 tUSDC）
2. 执行计划（任务 3 的第 4-5 步）
3. **执行计划后**：再看一次余额，算算多了多少

> **此时请对比**：到账的 tUSDC 和你之前看到的"担保底线"，是多还是少？如果少了，有没有额外一笔补偿到账？

---

### 任务 5：查看结算结果

交易完成后，页面会显示三种结果之一：

| 结果 | 含义 | tUSDC 变化 |
|------|------|------------|
| ✅ 履约成功 | 到账达到保证值，保证金退还运营方 | 余额增加 = 实际 swap 输出 |
| ⚠️ 差额赔付 | 到账不足，从保证金里补给你 | 余额增加 = swap 输出 + 赔付（两笔到账！） |
| ❌ 交易失败 | Swap 没成功，退你本金 + 失败补偿 | MON 退回 + tUSDC 补偿到账 |

> **此时请回答**：
> 1. 你最终拿到了多少钱？比预期的多还是少？
> 2. 如果有赔付，你知道为什么触发赔付了吗？
> 3. 整个流程中哪个步骤让你最困惑？

## 给 Dev：如何切换测试场景

通过调整 MockDex 汇率，可以让测试者看到不同结果。在 `agent/` 目录下执行：

### 场景 1：正常履约（不需赔付）

```bash
# 设汇率 = 100，实际到账 ≥ 担保底线，保证金全额退还
./agent setrate 100
```

测试者执行后看到：✅ 履约成功，余额增加 100 tUSDC。

### 场景 2：差额赔付

```bash
# 设汇率 = 50，实际到账 < 担保底线，自动从保证金赔付
./agent setrate 50
```

测试者执行后看到：⚠️ 差额赔付，余额增加 = swap 输出 + 赔付（两笔到账）。

### 对比效果

| 场景 | 汇率 | 测试者支付 | 测试者收到 | 保证金 |
|------|------|-----------|-----------|--------|
| 正常履约 | 100 | 1 MON | ~100 tUSDC | 退还运营方 |
| 差额赔付 | 50 | 1 MON | ~50 + ~20 = 70 tUSDC | 赔付给用户 |

> **给测试者看这个对比表格**，他们就能直观理解"有担保 vs 没担保"的区别。

### 测试流程建议

1. 先跑**场景 2**（差额赔付），测试者能看到"赔钱了"——印象最深
2. 再跑**场景 1**（正常履约），让测试者对比两者差异
3. 每次执行前后让测试者**看 tUSDC 余额变化**，数字比文字更有说服力

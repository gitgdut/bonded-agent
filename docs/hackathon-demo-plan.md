# Bonded Agent — 黑客松 Demo 说明

> 一份给你队友和评委看的文档，不需要懂技术也能理解。

---

## 一句话说清楚

**Bonded Agent 是一个"有保险的 Swap"**：AI Agent（运营方）在你交易前先锁定一笔保证金，如果实际到账低于承诺值，合约自动从保证金里扣钱赔给你。

---

## 痛点：为什么需要这个？

平时在 DEX 上 swap，你看到的报价和你实际到手的是两回事：

- 报价时显示 1 MON = 100 USDC
- 交易执行时可能滑点、MEV 抢跑、池子被抽干
- 最后到手可能只有 80，甚至交易失败

**你去哪说理？没地方。** Bonded Agent 解决的就是这个——运营方提前锁定保证金，差额自动赔。

| 运营方锁定保证金 | **20 tUSDC** | 如果到账不足，从这里赔你 |

### 这笔交易实际发生了什么

```
1. 你输入 1 MON，点击"获取担保报价"
2. AI 代理查询链上汇率（100 tUSDC/MON），告诉你预计到账 100 tUSDC
3. AI 代理锁定 20 tUSDC 保证金到合约，承诺"至少到账 90 tUSDC"
4. 你点击"同意并执行 Swap"
5. 合约执行 swap，实际到账 100 tUSDC
6. 100 ≥ 90，达标！运营方保证金全部退回
7. 你收到 100 tUSDC ✅
```

## 如果出问题了会怎样？

### 情况 A：滑点导致到账不足

比如市场突变，实际只到了 50 tUSDC，低于保证的 90。

| 步骤 | 发生什么 |
|------|----------|
| 实际到账 | 50 tUSDC |
| 保证值 | 90 tUSDC |
| 差额 | 40 tUSDC |
| 从保证金赔付 | 20 tUSDC（保证金上限） |
| 你最终收到 | 50 + 20 = **70 tUSDC** |

> 这时候你会得到 70 tUSDC，虽然没到 90（因为保证金有上限），但比没有保障时的 50 好多了。

### 情况 B：交易直接失败

比如合约出 bug，swap 根本没执行成功。

| 步骤 | 发生什么 |
|------|----------|
| 本金 | 1 MON 全额退还 |
| 失败补偿 | 额外赔你 5 tUSDC |
| 你最终收到 | **1 MON + 5 tUSDC** |

## 技术架构（给懂技术的队友）

```
用户浏览器（Next.js）
    │
    ├─→ Go Agent（运营方后端，:8787）
    │     ├─ /quote       → 模拟报价
    │     ├─ POST /plans  → 创建担保计划（锁定保证金）
    │     └─ GET /plans/:id → 查询计划状态
    │
    └─→ 链上合约（Monad Testnet）
          ├─ MockDex.swap()           → 执行代币兑换
          └─ BondedExecutor
               ├─ openPlan()          → 锁定保证金，创建计划
               ├─ executePlan()       → 用户执行 swap + 自动结算
               │    ├─ 达标 → 退保证金
               │    ├─ 不足 → 从保证金赔付
               │    └─ 失败 → 退本金 + 失败补偿
               └─ cancelPlan()        → 运营方取消未执行计划
```

**核心创新点**：赔付逻辑完全在链上（智能合约），不依赖 AI 判断或人工审核。保证金锁在合约里，运营方无法单方面挪用。
